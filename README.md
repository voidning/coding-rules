# Coding Rules

两份面向 AI 编码助手的通用规则，适用于不同语言、框架和项目：

- [复用优先](rules/reuse-first.md)：先检查已有能力，再决定复用、局部实现或新增依赖。
- [深模块](rules/deep-modules.md)：在抽象有明确价值时，设计能隐藏复杂度、降低调用者负担的接口。

规则不预设技术栈、目录结构或包管理器。项目的具体选型、运行环境、目录边界和检查命令应留在项目自己的约定文件中。

## 使用方式

把所需文件复制到项目的 `rules/` 目录，并在编码助手读取的项目指令文件（如 `AGENTS.md`）中加入以下内容。若使用其他目录，请同步调整路径。

```markdown
## 编码规则

- 新增实现或扩展现有功能前，先读取并遵循 `rules/reuse-first.md`：检查已有能力，按语义和约束决定复用或新增实现。
- 新增或调整抽象边界时，先读取并遵循 `rules/deep-modules.md`：降低调用者的理解和使用成本，仅在有明确价值时提取抽象。
```

这两份规则可以独立使用，也可以组合使用。复制文件后，仍需通过所用助手支持的项目指令机制引入；仅存放文件不代表助手会读取。

## 配合项目约定

在项目自己的约定文件中写清实际使用的技术栈、目录与依赖方向、依赖审批要求及验证命令，避免把这些内容写进通用规则。

复用优先负责判断“是否已有合适能力、是否需要新增实现”；深模块负责判断“是否值得抽象、接口应该如何设计”。找不到可复用代码，并不意味着必须创建公共模块。

执行授权以用户指令和项目约定为准，通用规则不要求重复确认已获授权的行动。

## 验证效果

可用小修复、已有能力复用、新增模块三类真实任务检查效果：改动是否正确，是否减少重复实现，是否出现无价值的包装层、过度搜索或不必要的询问。根据实际结果调整规则，不以文本长度作为唯一标准。

## 设计来源

深模块理念参考 John Ousterhout 的《A Philosophy of Software Design》第 4–6 章。本仓库提供的是面向编码助手的实践表述，并非书籍原文摘录；依赖审批与交互流程属于本规则的执行约定。
